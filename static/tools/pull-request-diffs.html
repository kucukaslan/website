What does a PR diff actually show?

GitHub and modern Bitbucket show what the source branch changed since its common ancestor; GitLab also supports merge-result comparisons. Neither view alone proves a merge is safe.

Verify the trees, not just the illustration
All seven examples come from real Git output embedded in this HTML. Download the Python fixture script to create inspectable repositories and the same diff data. It uses Python 3 and Git 2.38 or newer, creates a new directory, and needs no network access.
python3 pull-request-diffs.py ./pr-diff-examples
cd pr-diff-examples/same
git diff main...feature
Compute a local preview
Git 2.38 introduced this merge-tree mode. Exit 0 means a clean textual merge; exit 1 means conflicts. Other failures are errors, not merge previews.
git merge-tree --write-tree main feature > merge-output.txt
status=$?
cat merge-output.txt
if [ "$status" -eq 0 ]; then
  tree=$(head -n 1 merge-output.txt)
  git diff main "$tree"
fi
What a conflicted run actually returns
Git still writes a tree, with conflict markers for this text conflict. It prints the tree ID, conflicted file stages and messages; the exit status is 1. This is an unresolved tree, not an approved integration result.
The marker contents live inside that returned tree:
tree=$(head -n 1 merge-output.txt)
git show "$tree:config.py"
Inspect the host’s provisional merge
Use a remote pointing at the target repository. Replace 123 with the PR or MR number. Fetching these refs reads a server-generated preview; it does not merge your branch.
GitHub
git fetch origin refs/pull/123/merge
git show --no-patch --format='%H %P' FETCH_HEAD
git diff FETCH_HEAD^1 FETCH_HEAD
PR workflows use the merge ref. The PR API reports a test merge SHA when mergeable; calculation can be pending.
GitLab
git fetch origin refs/merge-requests/123/merge
git show --no-patch --format='%H %P' FETCH_HEAD
git diff FETCH_HEAD^1 FETCH_HEAD
GET /projects/:id/merge_requests/:iid/merge_ref requests an up-to-date merge ref when possible; conflicts return HTTP 400.
Refs can be absent, pending or stale. Check both parent SHAs against the current target and source SHAs before interpreting a preview. The commands above compare against the preview’s own target parent, not a potentially newer main. Run each diff only after a successful fetch: a failed fetch can leave an older FETCH_HEAD behind.
Two dots and three dots depend on the command
CommandMeaning
git diff A..BSnapshot A → snapshot B; same as git diff A B.
git diff A...BMerge base of A and B → B. Direction matters.
git log A..BCommits reachable from B, excluding those reachable from A.
git log A...BSymmetric difference: commits reachable from either side, but not both.
References: git diff · git log.
Glossary and scope
Tip / HEAD: the latest commit of the branch being discussed. Merge base: a best common ancestor in the commit graph. Tree: a snapshot of tracked files and directories, without commit history. Hunk: one region of a textual diff. Merge ref: a name pointing to a temporary merge commit.
These fixtures use one merge base, ordinary text files and Git’s default merge behavior. Rename detection is heuristic. Multiple merge bases, custom drivers, merge options, rebase and cherry-pick workflows need their own analysis. A clean merge proves only that Git combined the text without a conflict.
